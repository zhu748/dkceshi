# 图片、文件复用与 GIF 抓包核对

## 样本与结论

本轮核对用户提供的两份原始 HAR：普通上传样本 49 条记录，以及重复上传/GIF/删除会话
样本 59 条记录。没有使用其中的认证信息访问上游。仓库仅保存第二份样本的脱敏协议特征
`tests/fixtures/android_app_2_7_1_gif_reuse.json`，不保存原始 HAR、文件正文、文件名、
会话/设备/账号 ID、签名下载地址、token 或提示词。

第一份样本有 4 次 WebP、2 次 TXT、1 次 PDF 上传；其中同一张 WebP 被上传两次，
字节一致但上游 ID 不同。四次纯文字追问沿用会话/父消息 ID，ref_file_ids 为空。
一次只发三张图片的 completion 使用空 prompt，证实 App 支持纯图片输入。

第二份样本有 3 次 WebP 和 3 次 GIF 上传：

| 组 | 文件字节数 | 尺寸 | 帧数 | 观察 |
| --- | ---: | --- | ---: | --- |
| 相同 WebP | 71738 | 1080 × 1920 | 1 | 三次上传文件部分逐字节相同，各返回不同 ID |
| 相同 GIF | 743502 | 300 × 310 | 16 | 三次上传逐字节相同，动画保留，各返回不同 ID |

两次 GIF 会话被删除后，App 再次上传同一 GIF 并取得新 ID。
这证明重新选择图片会重新上传，不能证明旧 ID 已失效，也不能证明旧 ID 删除后仍有效。
HAR 没有“新会话引用旧 ID”的成功样本。本项目的跨请求文件缓存是额外优化，
并不把它描述为 App 已有的内容去重功能，也不宣称跨会话长期复用已通过真实上游验证。

## 上传复用

所有协议通过共享 DeepSeek Client 上传。默认启用有界、进程内、绝对 TTL 的文件 ID 缓存；
首次仍实际上传，重复数据在同一调用者、账号/凭证、安装身份和处理参数下可复用。
文件名、MIME、purpose、思考开关和压缩设置也属于键，避免把不同解析/处理方式的文件混用。
缓存放在压缩和随机文件名生成之前，不保留文件字节，避免内存随上传体积增长。

| 配置 | 默认 | 含义 |
| --- | ---: | --- |
| `DS2API_UPLOAD_CACHE_TTL_SECONDS` | 900 | 本地缓存寿命，0 禁用，最大 86400 |
| `DS2API_UPLOAD_CACHE_MAX_ENTRIES` | 256 | 元数据项数，0 禁用，最大 4096 |

命中后先查询上游状态，再决定复用。确定不存在或处理失败时重传本次输入；鉴权、网络、
限流失败保持错误语义，不盲目重传。并发相同请求合并上传/查询，并分别处理请求取消。
删除会话成功时保守失效该凭证的全部缓存，不允许在途操作把失效项重新放回。
缓存不绕过账号绑定，也不改变多账号调度：不同账号各自拥有上传和缓存。
用户显式传 file_id 时继续直传引用；没有原始文件时不能自动重传。

需要稳定命中时，可先 `/v1/files` 上传并记录 `id`/`account_id`，后续用 `file_ids`
及 `X-Ds2-Target-Account` 指定原账号。跨请求 Base64 相同且处理参数一致也可自动命中。
服务重启、凭证更新、到期、容量淘汰及会话删除均可能导致再次上传。

项目继续等文件 SUCCESS 后再开始聊天。HAR 中存在轮询、上传、completion 的时间重叠；
等待成功是本项目的保守策略，不声称完全复制 App 调度时序。

## 纯图片输入

剥离图片块时保留已上传图片对应的空文本 user 轮次，并先保存文件 ID 引用。
修复首轮仅图片上传成功后因 messages 为空而 400，以及纯图片追问被当作上一轮的问题。
不为用户编造“请描述图片”等文字；共享 prompt 仍采用项目原有的角色标记。
OpenAI Chat、Responses 的流式/非流式、已有 file_id 及 Responses 单对象 input 均覆盖回归。
GIF 不执行 JPEG/PNG 的有损转码，multipart 文件部分保留全部字节、帧、延时和循环设置。

## 请求指纹

第二份 HAR 提供 11 类端点的 HTTP/2 请求头形态。Go 的本地 HTTP/2 收包测试验证实际
发送的伪头顺序、普通头顺序、静态值、GET 无内容头、空会话创建长度 0、JSON UTF-8 字节长度，
以及上传无 Content-Length。Node 使用相同脱敏 fixture 验证头部构造并保留已有实线 SSE 测试。

本轮修正：

- 已知长度的 multipart 请求也强制使用未知长度流，防止底层 HTTP/2 库补回 Content-Length。
- Node GET/HEAD 去掉 Content-Type/Content-Length，multipart 不添加 Content-Length。
- Node check_device 把 authorization 放在身份字段前，与 Go 一致；大小写重复头确定性合并。
- Go 与 Node 都过滤浏览器的 Accept-Language/sec-fetch-mode 及 HTTP/2 不允许的连接头。
- 新增 `DS2API_DEEPSEEK_SEND_INSTALLATION_HEADER=0`，在默认有序 Go HTTP/2 和 Node 路径
  省略 x-device-id，匹配本次样本的可选头部形态。缺省维持已有安装头行为；此开关不修改
  安装身份、登录数据、check_device JSON 或缓存隔离键。旧传输回退本来就不保证这些线序。

所有新样本均未发送 x-device-id，但既有 APK 静态证据包含该字段，因此不凭单组抓包
删除安装身份机制。设备型号、rangers ID 和授权材料仍来自各自账号配置，不复制抓包值。

HAR 不提供 TLS ClientHello、HTTP/2 SETTINGS/窗口/HPACK 的原始字节。本轮没有编造
Android 36 TLS 指纹或宣称 JA3/JA4 等价；Go 保留 Android OkHttp 兼容预设，Node 使用运行时 TLS。

## 验证

新增测试覆盖缓存命中免 PoW/上传、原账号/调用者/凭证/处理参数隔离、并发合并、取消、
非滑动 TTL、容量淘汰、上游缺失与失败重传、查询故障不重传、删除后失效及在途失效保护。
使用生成的动画测试图，不将用户图片提交到仓库。新 Node fixture 测试加入正式单测入口。
质量检查脚本补齐执行位，保证仓库声明的 `./scripts/...` / `./tests/scripts/...` 可直接执行。
