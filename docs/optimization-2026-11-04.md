# 恢复、用量与持久化优化（2026-11-04）

基于 `8a6cb8f` 的本轮改动，落实审查发现的四项缺陷，并完善共享换号预算、失败会话回收、持久化计算和回归覆盖。

## 已落实的修改

| 范围 | 修改及生效行为 |
| --- | --- |
| PoW 凭据恢复 | Go 获取 PoW 时成功刷新的 Token、请求头及到期信息同时返回 Node；后续 completion 使用同一组新凭据 |
| HTTP 200 鉴权错误 | Go/Node 都识别 40001/40002/40003 和既有鉴权消息；限流、封禁、禁言先于鉴权文本判断；普通 403 保留独立语义 |
| Vercel 输入用量 | Prepare 返回包含文件的初始 token 数；校验及 release 使用共享 Go 计算器，包含 HISTORY/TOOLS、引用附件与实际重试提示词 |
| 最终 SSE 与账本 | 现有 release 请求返回同一份最终 usage，Node 复用于最终帧；不新增控制请求。慢删除在 usage 响应送达后执行 |
| 取消与回退 | PoW 阶段取消记录已有生成；未发送的重试提示词不计入。仅 prepare 的租约不产生消费。Release 失败保留完整输入基数及估算回退 |
| 用量页缓存 | JSON 解析失败或 items 结构无效时保留已有账本和 ETag，并显示错误；不把坏响应发布为空账本 |
| 共享恢复预算 | 每请求最多三个替代账号；上传、上下文、会话、PoW 与 completion 共用。换号排队及取 Token 累计最多 30 秒，同账号刷新不扣替代账号数 |
| 会话回收 | 按 auto_delete 策略，将被替代的已登记会话交给既有固定队列；清理绑定原账号并读取该账号最新 Token；回调并发退休时只执行一次 |
| 登录协同 | 等待者只复制所需的 Token 和设备凭据，避免复制整个请求、账号尝试记录和资源回调 |
| 历史摘要 | 更新一条记录时只重建它的摘要，在相同创建时间内调整位置；保留原有完整重建回退和同步写盘规则 |
| 账本检查点 | 聚合键未变化时复用排序；新增键、导入和清空会失效缓存。写入失败保留 dirty，flush 期间并发记账不会丢失 |
| 编排维护 | Node 凭据/PoW 生命周期和用量状态分别移入 upstream_connection、usage_accounting；账号切换从 request.go 移入 account_switch.go |

原有账号固定、工具调用验证、正文交付后的防重放及文件格式保持兼容。新能力通过 prepare 字段协商；旧桥继续使用原有重试上限及计数回退。

## 本机性能测量

环境为 Linux amd64、AMD EPYC 9V74、Go 1.26.0。账本前后使用同一输入与同一基准，三次运行各两轮，取中位数。历史摘要基准在同一进程比较完整重建与增量更新。

| 测量项 | 修改前 | 修改后 |
| --- | ---: | ---: |
| 1 万条稳定聚合键的 flush | 13.22 ms | 9.39 ms |
| 10 万条稳定聚合键的 flush | 145.62 ms | 89.92 ms |
| 50 条历史的摘要更新 | 30.36 μs | 0.89 μs |
| 历史摘要更新分配 | 19,960 B / 54 次 | 176 B / 1 次 |

账本基准包含快照、排序和编码，使用内存写入替身，未测量真实 fsync。10 万条场景本机耗时下降约 38%；首次 flush 或持续新增聚合键仍需要排序。排序缓存只保留原 map 键的字符串头，64 位环境每十万条约增加 1.6 MB 常驻空间，不复制键文本。

历史基准只测摘要计算，不包含文件编码、同步写盘或整个 HTTP 请求。历史 Store 仍在锁内持久化；账本仍按既有周期重写完整检查点。这轮没有引入异步历史队列、增量日志或新的迁移格式。
