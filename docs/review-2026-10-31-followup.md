## 第 8 轮：流式结束后的资源回收

`ConsumeSSE` 在主动结束或无内容超时时可以直接返回，但后台解析泵仍使用调用方的长生命周期上下文。
当上游不再发送数据且不关闭连接时，后台读取会继续阻塞，占用协程、连接及缓冲区。

修复为每次消费建立独立子上下文，在收尾回调之前取消旧读取；调用方上下文仍可用于后续补偿。
关闭异常会记录日志。另移除 `ReadBytes` 返回值到通道之间的一次重复复制，因为该返回值本身已拥有独立字节。

回归：`internal/stream/lifecycle_test.go` 使用可阻塞的正文，确认提前结束与超时都会关闭读取且不取消父上下文。
修改前两个案例均失败；修复后 `stream`、`sse`、`completionruntime` 通过。

## 第 9 轮：账号限速和满载性能

- 下调每分钟阈值时，原代码只处理“提高阈值后恢复”，当前窗口已达到新上限的账号仍可再取号。
  现在重新计算当前窗口的限速状态，下调立即生效。
- 已触发且正在等待池锁的旧定时器，即使调用过 `Stop` 也可能继续运行，清空后来窗口或替换账号条目的计数。
  回调现在同时检查账号条目身份和窗口开始时间，只能清理自己的窗口。
- 全局并发已满时，原代码仍遍历每个候选账号，重复检查不可能满足的全局条件。
  取号和等待者匹配现在直接拒绝该次获取，避免无效全表扫描。

回归：`rate_limit_updates_test.go` 覆盖阈值下调、旧窗口、已替换条目和有效定时器；账号池与鉴权模块通过。
既有容量提升唤醒、工具池匹配和取消场景继续通过。

## 第 10 轮：Responses 缓存可靠性与内存分配

原代码的深复制失败时返回 nil，但随后可以成功编码这个 nil，导致非法 JSON 覆盖原先有效的缓存。
另一个问题是 TTL 只在缓存创建时读取，后续配置热更新没有效果。

现在响应与续接上下文各编码一次，缓存保存不可变 JSON，读取时单独解码所需部分。
编码错误在替换原条目之前退出，保留旧数据；仍通过统一数值解码器保留大整数精度。
TTL 热更新只影响之后写入的记录，现存记录沿用原期限；无效 TTL 保留默认回退。

回归覆盖非法响应/上下文、数字精度、空上下文、替换记账、256 条容量、过期回收、热更新及默认回退。
已有调用方隔离、嵌套对象隔离、多轮续接与 `store:false` 测试继续通过。

## 第 11 轮：超限代理订阅

原抓取器只读取前 16 MiB 后就解析。如果这个前缀恰好是有效 YAML，就会把不完整订阅当作完整结果，
可能造成节点静默缺失。现在最多读取上限加一字节，超限明确失败，恰好达到上限仍可使用。

`subscription_limit_test.go` 先复现“超限但成功返回两个节点”，修复后整个 Mihomo 模块通过。

## 第 12 轮：管理台异步会话与状态

- 旧登录验证完成后可能重新登录已退出的用户，或清除后来建立的新会话。
  会话控制器现在取消旧验证并检查请求身份；旧 token 的 401 不能注销当前新 token。
- 原代码分别从两种存储读取 token 和过期时间，可能混配，且旧的记住登录可覆盖当前标签页登录。
  现在成对读取，标签页会话优先；新登录清除另一处旧会话。存储不可用时保留内存登录，主动新登录优先于旧存储。
- 账号搜索/分页、队列和配置读取缺少过期请求保护，迟到响应可能覆盖新结果或提前清除 loading。
  现在使用共享请求世代控制，取消旧请求，在 JSON 读取后再次检查，卸载时清理请求。
- 可选的配置草稿持久化失败不再丢弃成功取得的配置；重复提示消息会替换旧计时器。

新增 7 项会话/请求控制测试，覆盖退出、新登录、旧失败、旧 401、存储配对、存储异常与内存会话恢复。
这些测试验证真实会话控制模块；React 页面整体由生产构建校验，未宣称已做浏览器端端到端测试。

## 第 13 轮：PoW 预取身份与容量

直通请求没有托管账号 ID，原代码将它们写入同一个空账号键。先缓存 token A 的结果后，token B 的预取会被跳过，
后续可能取得 A 的 proof。现在托管请求按账号、直通请求按 token 的 SHA-256 摘要区分，并继续区分目标 endpoint。
缓存键不保存原始直通 token。

原缓存还会无限积累不同身份的条目。现在缓存与正在预取的条目合计最多 256 项，写入时回收过期项，
满载时只淘汰已完成的旧结果；全部槽位都在预取时跳过额外预取，同步获取路径仍可工作。

回归先复现“两个 token 仅产生一份缓存”和“容量增长到 300”；修复后覆盖真实 `GetPowForTarget` 命中隔离、
过期回收和满载时保留正在预取的任务。client 全量测试及 race 通过。

## 第 14 轮：让语法门禁有实际覆盖

仓库删除旧阶段目标清单后，默认 Node 语法门禁一直以 `checked=0` 成功退出。
现在默认回退到 Git 中已跟踪及未被忽略的 `.js/.mjs/.cjs` 源码与脚本，当前检查 102 个文件。
显式指定不存在的目标清单会报错。JSX 继续通过 WebUI 构建检查；行数门禁仍因清单为空而检查 0 项，不能视为完整覆盖。
