# 安全与运行时约定

## 凭据、会话和备份

- Responses 的托管 Key 与直连 Token 使用独立缓存命名空间。删除托管 Key 后，原字符串不再能够读取或续接该 Key 的缓存响应；不存在的 ID 和无权读取的 ID 均返回 404。
- 新设置的管理员密码使用随机盐的 bcrypt-SHA256（bcrypt cost 10）。SHA-256 预散列使长 UTF-8 密码也可完整参与校验，避免 bcrypt 的 72 字节限制。现有 `sha256:` 哈希仍可登录；修改密码后使用新格式。
- 新密码至少需要 8 个 Unicode 字符。修改密码会失效已有管理会话。
- 建议设置独立随机的 `DS2API_JWT_SECRET`，尤其在多实例部署中应使用相同的值；未设置时仍保留现有凭据回退行为。JWT 校验限制签名算法为 HS256，并校验 admin 角色及过期时间。
- `POST /admin/login` 按客户端连接 IP 限流：初始允许 10 次尝试，每 30 秒补充一次。管理 API 的直接密码鉴权共用该失败预算，防止绕过登录接口猜测密码；成功密码鉴权重置预算，已签名管理会话不受失败预算限制。超限返回 429 和 `Retry-After` 秒数。最多保存 1024 个来源的预算。登录请求体上限 16 KiB。
- 限流默认使用原始 TCP 对端，避免伪造转发头绕过限制。只有在可信反向代理已经清理客户端转发头时，才设置 `DS2API_TRUST_PROXY_HEADERS=1`（或 `true`）使用代理解析后的 IP。该开关不配置代理地址白名单，网络入口必须由部署者保证可信。
- 管理台配置只保留在当前页面内存中，不再把 API Key 写入持久化草稿。加载页面、登录和退出时清除旧版 `ds2api_env_config_draft_v1`。未同步到 Vercel 的修改仍需在部署实例有效期间完成同步。
- 配置导出的 `config`、`json` 和 `base64` 来自同一份快照，均移除内部工具标记密钥与账号运行时 Token。导出的账号密码和托管 API Key 是备份内容的一部分，仍应妥善保管。
- 新配置文件及从示例创建的配置默认采用 0600 权限；保存既有文件时保留操作者已有的权限设置。

## 配置事务与账号占用

`Store.Update` 和 `Store.Replace` 先持久化候选配置，成功后再发布内存状态、凭据索引和设备版本。保存返回错误时不发布候选配置。主配置和订阅文件分别采用临时文件替换；若订阅文件已写入而主配置写入失败，会恢复旧订阅文件。若恢复本身也遇到磁盘故障，错误会同时返回；这不提供两个独立文件之间的崩溃原子性。

删除账号会立即停止新调度，但其正在执行的请求继续占用并发名额，直到实际结束。账号获取期间的集成回调若 panic，会先释放该请求占用的名额。

保活间隔拒绝 NaN、Infinity 和非法区间。运行时解析也防御非有限值，避免异常输入触发 panic 或缩短为一秒保活。

`POST /api/show` 的模型查询正文上限为 64 KiB，超过返回 413；限制对缺失或伪装的 Content-Type 同样有效。JSON 预校验也使用这一上限，避免在业务处理前先缓冲大正文。语音正文上限为 1 MiB。

## Vercel 流式控制进程

Vercel Go 函数存在响应缓冲，流式输出继续由 Node Runtime 承担。Node 的每个温实例启动一个本地 Go 控制进程，准备、PoW、校验、切号与释放均通过其 `127.0.0.1` 临时端口完成。完整流式生命周期不再向部署域名发起控制请求，因此不会因平台将控制请求分配给另一个 Go 实例而丢失租约。

- 构建时执行 `node scripts/build-vercel-control.mjs`，生成 Linux amd64 可执行文件 `internal/runtime/vercel-control`；`vercel.json` 明确将它包含进 Node 函数包。当前编译产物约 36 MiB。
- 构建优先使用 PATH 中可用的 Go；可用 `DS2API_GO_BINARY` 指定工具路径。没有 Go 时，从官方渠道下载 Go 1.26.0，并依据官方清单校验 SHA-256。此分支需要构建环境提供 curl、tar 与外网访问。
- Node 内并发请求复用同一个控制进程。启动失败在 20 秒内返回 503；进程退出后，新请求可以重新启动它，进行中的请求不会将旧租约迁移到新进程。
- 控制服务器只监听回环地址。内部控制接口继续要求 `DS2API_VERCEL_INTERNAL_SECRET`，未配置时回退到 `DS2API_ADMIN_KEY`，均缺失时拒绝内部请求。就绪握手不携带凭据。
- 父进程结束关闭 stdin，控制进程随之关闭 HTTP 服务、后台任务和临时状态。Node 客户端取消请求时仍调用同一控制进程释放租约。
- 默认历史、统计与限额文件位于控制进程独立的临时目录。不同 Node 温实例的配置热修改、统计和账号额度仍是实例级状态；这不是分布式账号池或持久数据库。需要集群级一致限额及持久历史时，应使用常驻单实例后端或另行部署共享存储。
- 非流式请求、其他协议入口仍由原 Go 函数处理。Vercel 配置修改应通过管理台同步并重新部署后供新实例一致读取。

在 Linux amd64 环境可运行以下本地烟雾检查，无需上游账号：

```sh
node scripts/build-vercel-control.mjs
node tests/scripts/smoke-vercel-control.cjs
```

CI 同时运行控制进程构建与烟雾检查、原有 Go/Node 门禁，以及鉴权、配置、账号池、保活和统计核心包的 race 检查。
