# 项目审查与性能优化记录（2026-10-31）

本页记录第一阶段七轮结果；后续见[第二阶段全面审查与修复](review-2026-10-31-followup.md)。

审查基线：`ac10fd0`，分支 `ceshi`。本次在本地工作区完成七轮“定位 → 修改 → 验证 → 复核”，
重点处理可复现的正确性问题、并发数据可靠性，以及能够测量的性能浪费。

本轮收敛条件是：已确认问题有针对性回归，相关模块和全量门禁通过，选定性能热点有前后对比，
业务行为变化同步文档。这里的收敛不表示整个项目已无缺陷，或所有部署场景已达到性能上限。

## 项目主链路与审查重点

DS2API 将 OpenAI Chat/Responses、Claude、Gemini 请求转换为 DeepSeek 网页对话请求。
主要处理路径是：HTTP 路由与鉴权、账号选择、标准请求归一化、提示词/文件处理、上游 completion、
SSE 收集、统一 assistant turn、目标协议输出。Vercel 还维护 Node 流式路径，必须注意 Go/Node 行为一致。

| 层次 | 主要模块 | 本次核查内容 |
| --- | --- | --- |
| 请求与调度 | `internal/httpapi`、`internal/auth`、`internal/account` | 错误传递、重试边界、账号队列及既有回归 |
| 上游与流 | `internal/deepseek`、`internal/sse`、`internal/stream` | 终止信号、读取异常、快照去重、字符边界 |
| 共享业务 | `internal/completionruntime`、`internal/assistantturn` | 部分结果是否被错误接受、工具修复、协议之间的共享行为 |
| 数据存储 | `internal/usagestats`、`internal/chathistory`、Responses 缓存 | 落盘顺序、锁范围、数据复制及历史查询 |
| 管理台 | `webui/src/features/usage`、`chatHistory`、应用与构建入口 | 轮询、过期响应、ETag、图表容量与加载成本 |

本次没有调整上游 TLS 指纹、账号调度策略或提示词主逻辑。修复底层读取错误时采用共享收集器与
assistant turn/runtime 路径，避免由某一个协议适配器单独定义业务规则。

## 七轮结果

| 轮次 | 原问题及影响 | 修改与复核 |
| --- | --- | --- |
| 1：用量数据与稀疏历史 | `sameUsageRecords` 比较了不存在的字段，调用次数/费用不变时 token 变化被忽略；`__proto__` 等名称破坏分组；全部历史按每个自然日迭代 | 改为比较真实 token 字段，分组使用无原型字典，直接将已有日期分配到至多 180 个桶。先复现两个失败测试，再通过用量/CSV 回归 |
| 2：历史详情请求竞争 | 旧详情未完成时新选择的请求被跳过；迟到响应和跨记录 ETag 会干扰当前选择；轮询停止时可能缺少最终详情 | 独立详情资源负责取消、请求身份校验、同记录请求合并和按记录保存 ETag；选择变化立即加载新详情，完成后补取最新版本。可控异步测试覆盖旧响应、旧错误、迟到 JSON、304 与取消 |
| 3：账本持久化与设置 | 两个 flush 可以倒序覆盖磁盘，且 dirty 标记已被较新写入清除；保存设置后仍共享输入指针；落盘失败却改变运行中设置 | 单独串行化快照/写盘，磁盘 I/O 不持有记账锁；设置深拷贝，保存失败回滚；摘要及落盘排序移到记账锁外。三个问题均先复现，修复后用量模块与 race 检测通过，持久化竞争测试重复 10 次通过 |
| 4：续答快照 | Go 未去除相同长度的重复快照；Node 按 UTF-16 长度判断，可能误删不足 32 个字符的 emoji 增量；Go 对每个大段输入全文计数 | Go 字符串/Builder 与 Node 统一使用 Unicode 字符阈值；最多计数 32 个字符。测试覆盖 ASCII、中文、emoji 的 31/32/33 字符边界、相同/较短/较长快照以及真实收集路径 |
| 5：非流式断流 | 收集器丢弃底层读取异常，部分正文或工具可能被当成成功；工具修复虽记录失败却返回无错误 | 保留 `ReadError`，共享 runtime 返回 `502 upstream_read_error`，部分工具不能清除该错误；不将断流送入空输出补偿，也不修复/接受失败流中的工具。工具修复和保活传播失败。覆盖空正文、部分正文、部分工具、正常终止信号及修复失败 |
| 6：复核容量边界 | 未来日期导入可让“30 天”图表扩展为数千甚至更多点；历史详情的异步刷新仍可能持有旧选择 | 所有图表跨度最多 180 点，保留累计值；详情加载检查当前选择，并仅在当前详情落后时补取。十年未来日期样例由 3744 点降为 179 点，相关数据与详情资源回归通过 |
| 7：页面加载 | 用量页面业务与图表引擎一起加载，单个页面 chunk 约 560 KB | 图表按需加载并保留固定高度占位，摘要/筛选/导出不等待图表引擎；补充图表可访问名称。生产构建中用量业务包约 43 KB，图表独立加载 |

## 性能实测

| 场景 | 修改前 | 修改后 | 说明 |
| --- | --- | --- | --- |
| 9000 年跨度、仅 3 个有效日期的历史分桶 | 中位数 899.416 ms | 中位数 0.259 ms | 相同夹具，预热一次后运行 5 次；每次校验点数及 token 总量。原实现遍历约 329 万个日期，新实现处理记录和固定数量的桶 |
| 约 3 MiB 的独立中文 SSE 片段，前缀不相同 | 中位数 5.405 ms/op | 中位数 127.4 ns/op | Go 微基准各运行 3 次；均为 0 分配。收益来自长度阈值判断不再全文扫描；实际前缀比较仍需检查匹配部分 |
| 用量页面业务 chunk | 560.01 KB / gzip 185.91 KB | 43.43 KB / gzip 11.34 KB | 图表引擎改为独立的 517.14 KB / gzip 175.14 KB chunk；这是加载时机优化，不表示总下载量减少同样比例 |

这些结果对应具体算法与构建产物，不能直接换算为全站吞吐量或上游响应时间的提升。

复测命令：

```bash
node tests/tools/bench-usage-data.mjs
go test ./internal/sse -run '^$' -bench BenchmarkTrimContinuationOverlapIndependentDelta -benchmem -count=3
```

`bench-usage-data.mjs` 接受旧版 `usageUtils.js` 的文件路径，可对相同夹具进行版本间对比。

## 后续验证边界

- 未执行带真实账号的 `run-live.sh`。上游接口漂移、长会话续答、真实文件生命周期和账号切换仍需授权测试环境验证。
- 七个平台的编译不等同于在 macOS/Windows 上实际运行测试；当前实际单测环境为 Linux。
- 微基准包含故意放大的稀疏/长文本边界。生产 p50/p95/p99、内存峰值及并发吞吐需要带真实请求分布的负载测试。
- 图表引擎本身体积仍约 517 KB。进一步减小依赖需要评估图表功能取舍；本轮保留已有模块注册及渲染回归。
- 本轮没有证明“没有任何可优化空间”；没有实测依据的架构重写、协议行为变化和依赖替换未纳入已完成优化。

接口行为已同步 `API.md`、`API.en.md` 和 `docs/prompt-compatibility.md`。
新增回归已接入 Node 测试入口，Go 测试由现有全量入口自动发现。
