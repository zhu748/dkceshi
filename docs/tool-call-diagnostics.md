# 工具调用诊断

管理面板的「工具调用诊断」展示工具候选批次的解析、本地恢复、模型格式修复、
参数与工具策略校验、纠正生成，以及响应写入结果。只有实际出现工具候选或 required
工具策略失败的请求进入诊断；普通文本回答不会仅因请求附带工具目录而产生记录。

## 结果含义

| 结果 | 含义 |
| --- | --- |
| 直接解析成功 | 无纠正步骤，最终校验通过 |
| 本地恢复成功 | CDATA、参数标签简写、原生 DSML 或确定性参数归一化等恢复后通过 |
| 模型格式修复成功 | 模型修复通过调用身份、顺序、参数值与占位符保真检查，最终校验通过 |
| 重新生成后成功 | 先前输出被拒绝，后续新生成的输出通过；失败尝试仍独立保存 |
| 最终失败 | 当前输出不能交付，未继续重试或重试已结束 |
| 中断／取消 | 请求取消、进程重启或 Node 租约超时使流程未完整结束 |

一个主请求对应一条诊断，内部展开每次生成尝试和各个工具。格式修复请求是该次尝试的
阶段，不另占一条主记录。同名及同参数调用不会按值合并。受损残片的工具名尽可能从
协议身份中提取；无法确定时显示未知工具，不从声明目录猜测。无法确定原始序号的受损
调用显示 `#?`。

解析、Schema 校验与交付分别展示。无正式 Schema 的调用显示「未提供 Schema」。
整个批次被拒绝时，已经成功解析的兄弟调用仍显示「未交付」。服务端写入连接成功
不证明客户端收到了全部内容，也不表示外部工具执行成功。

## 保留与存储

- 默认采集，普通记录保留最近 20 条，可改为 50 条。
- 发生未解决的解析／校验失败或传输失败时自动锁定；后续重新生成成功不会解除锁定。
- 锁定错误不参与条数淘汰，进行中的记录也不参与淘汰。
- 关闭采集只阻止新记录；已有请求继续完成记录，原有记录保留。
- 「清理普通记录」保留锁定错误；「清理异常记录」和单条删除需要在界面明确确认。
- 失败详情独立于响应历史保存，不依赖响应历史的保留上限。

`DS2API_TOOL_DIAGNOSTICS_PATH` 指定索引文件，默认 `data/tool_diagnostics.json`，
独立详情放在同名 `.d` 目录。索引常驻内存，详情按需加载；详情及索引以临时文件、
同步和原子替换写入。重启时将未完成请求标为中断并锁定，保留其最后已落盘的证据。
存储失败显示在栏目中并写日志，不改变对外的工具调用处理结果。

单个文本快照最多保存 256 KiB 的首尾片段，附带原始字节数和截断标志；参数 JSON
以文本保存，避免前端重新解析大整数造成精度损失。下载 JSON 导出当前保存的证据，
不会补回已经截断的内容。诊断中不保存鉴权 Header 或上游 Token。工具参数可能包含
业务内容，接口沿用管理面板鉴权。

Vercel 使用项目现有的 Go prepare / Node stream 链路：租约关联同一诊断记录，Node
传递生成尝试序号和重试原因，Go 记录共享解析、修复和校验，release 补充最终状态。
默认路径为 `/tmp/tool_diagnostics.json`；这种本地文件方案不能提供跨实例及跨部署
的持久保留，需要长期统一保留时应配置适合部署环境的持久存储。

## 格式修复模型配置

在本栏目展开「格式修复模型」进行设置，配置对新进入的请求生效，独立于诊断采集开关。

- **跟随原请求模型（默认）**：使用标准请求的 `ResolvedModel`，即兼容别名映射后的实际
  上游模型，不固定使用一个修复模型。原生修复使用同账号的独立会话，开启思考、关闭搜索。
- **自定义 API**：选择 OpenAI、Claude 或 Gemini 格式，填写 Base URL 或完整生成接口地址、
  模型名称，按需填写 API Key。三种协议原生发送，不需要先转换成 OpenAI 格式。
- **修复超时**：默认 10 秒，可设置 1–300 秒。客户端取消和平台剩余期限优先；Node 的
  验证请求按配置预留修复时间，不再固定限制为 15 秒。
- **额外 JSON 参数**：按 API 提供商要求透传思考强度、thinking 等参数。自定义 API
  遵循模型默认思考行为；这里可以配置提供商要求的显式思考选项。不能覆盖模型、消息、
  工具目录、输出协议及主会话关联字段。

两种方式都只发送格式规范、修复约束、占位符清单和错误工具批次；不附带主对话历史或
文件。自定义 API 使用一个独立 user 轮次与非流式请求，分别适配三种协议的最终文本和思考字段。模型返回
格式后仍需通过完整性、参数保真、Schema 和策略校验。API 请求成功不等于修复成功。
自定义 API 失败时记录具体原因，继续走既有失败与纠正生成流程。

修复来源与实际模型显示在处理过程的「修复模型请求」阶段；响应归档的 `toolcall.repair`
也使用实际修复模型名。原请求仍使用自己的模型，修复配置不改变主请求的模型选择。

### 拉取、选择并保存模型

填写协议、地址和密钥后点击「拉取模型」，无需先保存配置，也无需预先知道模型名。
可以使用同一协议与主机下已保存的密钥，也可以填写新的密钥试拉取。返回列表中选择模型，
再点击「保存修复配置」。拉取操作不会修改配置；只有保存才写入所选协议和模型。
不支持模型列表的兼容网关仍可手动填写模型名。

| 格式 | 修复请求 | 模型列表 | API Key 请求头 |
| --- | --- | --- | --- |
| OpenAI | `POST /v1/chat/completions` | `GET /v1/models` | `Authorization: Bearer …` |
| Claude | `POST /v1/messages` | `GET /v1/models`，自动读取分页 | `x-api-key`；同时发送 `anthropic-version: 2023-06-01` |
| Gemini | `POST /v1beta/models/{model}:generateContent` | `GET /v1beta/models`，自动读取分页 | `x-goog-api-key` |

地址支持网关前缀、已有版本路径和完整生成地址。Gemini 也支持 `/v1`；接口模型列表中的
`models/` 前缀会转换成可选模型 ID。明确不支持 `generateContent` 的模型不进入列表。
每次拉取最多 20 页、1000 个模型，超过限制会提示仅返回部分结果。切换协议、地址或
密钥会取消旧的拉取请求并清空旧列表，过期结果不会覆盖当前选择。

三种协议统一只将最终文本交给修复校验。Claude 的 `thinking` 块、Gemini 标记为
`thought` 的文本单独归档；工具调用块、截断或过滤结果不会当作有效修复接收。
Claude 默认 `max_tokens=8192`，Gemini 默认 `generationConfig.maxOutputTokens=8192`
且只请求一个候选，可通过额外参数调整允许的生成设置。思考参数按各自原生格式配置。

API Key 只保存在权限为 `0600` 的服务端诊断索引文件中，管理接口只返回是否已设置。
留空保留旧密钥；可以显式清除。更换 API 格式、接口主机或 HTTP(S) 协议时，未重新填写的旧密钥会被清除。
API Key 不放入诊断记录或 Node prepare 响应；错误消息会遮蔽提供商回显的完整密钥。
记录清理和修改 20/50 条上限不会移除修复配置。Vercel 的临时文件存储限制同样适用于配置。

## 管理接口

所有接口位于现有管理员鉴权组中：

| 方法与路径 | 用途 |
| --- | --- |
| `GET /admin/tool-call-records` | 分页摘要，支持 `page`、`page_size`、`status`、`tool`、`search`、`pinned` |
| `GET /admin/tool-call-records/{id}` | 请求、尝试、各工具及阶段详情 |
| `POST /admin/tool-call-records/repair-models` | 使用尚未保存的协议、地址与密钥拉取模型；不要求已选择模型 |
| `PUT /admin/tool-call-records/repair-settings` | 保存修复来源、URL、模型、可选密钥、超时与额外参数 |
| `PUT /admin/tool-call-records/settings` | `{"enabled":true,"limit":20}`，上限只接受 20 或 50 |
| `DELETE /admin/tool-call-records?scope=normal` | 清理已完成普通记录 |
| `DELETE /admin/tool-call-records?scope=errors` | 显式清理已完成锁定异常 |
| `DELETE /admin/tool-call-records/{id}` | 删除已完成的指定记录 |

## 开发接入

诊断上下文由 HTTP 层建立，解析器只提供实际采用的恢复步骤；共享 `assistantturn`
最终校验后提交一次观察，`completionruntime` 记录重新生成和账号切换。中间收集用
Turn 在正常收集时不提交观察；读取中断直接退出时保存已收到的候选和错误，不执行模型修复。格式修复启用模型思考，思考内容单独存入修复子请求的响应归档；只有最终正文进入修复解析。格式修复返回文本
与最终通过校验是独立阶段，不能根据上游 HTTP 200 或旧修复日志判断成功。

客户端取消和交付错误在 HTTP 输出边界收尾。继续同一回答的 continue/resume 不创建
新的生成尝试；重新生成或更换账号后才开始新尝试。工具判断与重试资格保持原有共享
业务规则，诊断不触发额外模型调用。

## 失败路径、并发与保存一致性

- 各工具的 Schema 展示直接复用共享校验结果，不重复执行校验。策略或批次检查先行拒绝时，未执行的 Schema 检查显示跳过。
- Responses 校验后仍可能发生响应存储失败，客户端收到 `response.failed` 时，诊断保留失败和未交付状态；流式 HTTP 200 本身不表示调用已发送。
- 非流式与 Go 流式的读取中断、无法续传、续传失败、取消和写入错误，统一在共享运行时收尾保留工具候选。已经完成校验的原始证据不会被传输层文本覆盖。普通文本失败不会仅因带有工具目录而进入诊断。
- Node 验证与修复回调绑定生成尝试序号。旧尝试的迟到解析、修复、错误或配置更新不能改写新尝试；重新生成前未完成的旧尝试会关闭并保留失败原因，已结束请求不会仍包含运行中的尝试。
- 首个候选、每次最终校验、失败现场和请求结束同步保存。中间阶段及重试决策以 100 ms 窗口合并写盘，关键检查点刷新全部排队证据并取消旧计时器。进程突然退出可能丢失窗口内尚未保存的中间更新，已有失败检查点保留。
- 已有记录更新时保持索引顺序，新增或创建时间变化时才重排。索引提交失败会回滚内存索引与保留决策，不提前删除已提交记录；修订号只在成功提交后前进。新写入的详情文件可能已落盘，但提交失败不保证该次记录能在重启后检索，界面会显示存储错误。
- 只精确匹配值为 `1` 的现有内部 `__stream_prepare/validate/release/pow/switch/progress` 控制请求跳过主记录；其他 `__stream_*` 参数不绕过普通请求的采集或修复设置。
- 完整生成接口仅移除当前协议的后缀，不额外插入版本段。网关前缀中的 `/models`、`/messages` 等路径保持原样，例如 `https://example.test/gateway/models/v1/chat/completions` 直接使用该地址。
- 保存设置立即返回脱敏规范配置 `settings` 和 `revision`，前端同步更新表单；保存前或期间启动的旧轮询不能覆盖新值，重复提交被拦截。页面离开或鉴权上下文变化会取消未完成请求，迟到保存结果及错误不更新新会话。
- 隐藏标签页暂停轮询，回到页面立即刷新；详情读取错误独立于列表轮询，不会被下一次列表成功刷新清除。
- OpenAI 格式修复响应即使附带正文，也拒绝结构化 `tool_calls`、旧式 `function_call` 或非空 `refusal`；空数组和 `null` 兼容字段仍可接收。

## 生成中检查点与修复测试

- Go 的 Chat、Responses、Claude、Gemini 流式适配器使用同一候选探测器；沿用字面量、CDATA、代码块和标识归一化规则。首次截获工具候选即同步保存 `running` 原文证据，后续快照按 100 ms 窗口更新。探测不执行模型修复或最终校验，不会提前交付工具调用。若最终普通正文覆盖了隐藏思考候选，且未发生修复、失败或重试，则移除这条临时候选，避免污染工具诊断。
- Node prepare 返回是否启用候选检查点；启用时通过受内部鉴权和租约约束的 `__stream_progress=1` 回调保存，每秒至多一次且不并发发送。正文与思考各最多 256 KiB，保留原始字节数；长正文前缀后出现工具时，检查点优先保留工具起点。检查点失败只记录日志，平台突然终止时仅保证已保存的证据。
- Node release 在错误及取消路径复用共享失败观察，区分真实候选与仅附带工具目录的普通回答，并保存隐藏思考中的调用。迟到进度不能覆盖已经校验的尝试或后续生成。
- 同一生成尝试的最终校验 Promise 被复用。重试耗尽、换号失败或重复收尾不会再次调用修复 API；重新生成才清除缓存。继续同一回答的状态仍保留。
- 每条诊断的文本证据合计最多 4 MiB，优先保留最近尝试；达到上限时详情展示总量截断提示，并保留每个快照的原始字节数。活跃 Recorder 同样受此限制。错误说明另有单字段 8 KiB 上限。已锁定异常仍只由明确清理操作删除。
- 完成请求读取诊断开关和修复配置时使用成功提交后的不可变快照，不等待其他诊断的详情写盘；详情 JSON 的序列化移到存储锁之外。原有原子写盘与失败回滚规则保留。
- 自定义修复响应的完整 JSON（含思考）上限为 `min(max_output_bytes, 4 × max_repair_bytes)`，默认 4 MiB；模型列表仍独立限制为每页 4 MiB。

管理接口新增 `POST /admin/tool-call-records/repair-test`，接收完整、尚未保存的自定义修复配置。密钥按相同协议和源站规则解析；测试只发送固定的 `repair_probe(path=probe.txt)` 错误格式示例，使用真实生成接口并检查调用身份、占位符和参数值保真。返回 `success`、`protocol`、`model`、`elapsed_ms`；失败返回脱敏原因。测试不会保存配置、创建主请求诊断或使用主对话历史。管理面板明确标注此操作会调用所选 API。

修复阶段现在携带可选 `history_id`，面板可按需展开对应响应归档，查看修复模型思考与最终正文。响应历史被关闭、淘汰或清理时，显示不可用提示，独立诊断证据继续保留。搜索输入采用 250 ms 防抖；变更连接、模型或额外参数后会清除旧测试结果，过期响应不能覆盖新表单。
