# 正文回显生成提示词的修复

基线：v4.6.7（4fe0541）。附件只用于本地诊断，未将完整导出记录、客户端系统提示词或账号资料加入仓库。

## 证据和判断

- 截图对应记录在服务端导出中已包含异常 `content`，并非前端将系统提示词显示到正文。
- 该记录保存了 10,397 字符的正常代码修改思考，以及 586 字符的异常正文。正文近似复述生成的思考系统前缀，再以会话转录引言结尾。
- 实时提示词仍有最新用户任务及其后工具调用和结果；历史文件保存更早上下文。没有发现这条记录的最新任务被历史拆分丢弃。
- 正文对提示词的一处措辞有改写，且异常内容不在已保存的思考文本中，更符合上游回显输入的表现。导出没有原始上游 SSE，无法据此断言具体原始片段路径。
- 原有输出保护在遇到消息结束标记时截断，但把此前的回显正文当作有效答案，最终以成功 stop 保存。这一缺口已通过新增回归复现。

## 修改

- 在共享内容策略中增加与本次实际生成前缀绑定的回答开头检测，保留引用、代码和正常正文；限制短前缀缓冲大小。
- 在流式首次正文交付前拒绝回显；收集式和直接构造标准 Turn 的路径也执行同一验证。
- 保留回显原因直到最终验证，使用 `upstream_prompt_echo` / 502，按现有预算进行一次带明确反馈的重新生成。失败不会伪装为成功或账号限流。
- 拒绝从该次思考规划中恢复、修复或执行工具调用；正常思考通道不被转换成正文。
- 同步 OpenAI Chat、Responses、Claude、Gemini 和 Vercel Node，并覆盖短前缀的 EOF 收尾及重试状态重置。

## 验证范围

将附件中的 33 条记录分别交给 Go 和 Node 新检测器重放，两者均只命中截图对应的一条；其余 32 条的正文保持原文。Go 另覆盖五种分片大小，共 165 次样本检查。

新增用例覆盖默认及自定义前缀、逐字节分片、正常引用及代码、短回答 EOF、思考/正文分离、四协议流式路径、非流式重试成功与耗尽，以及 Node 流式反馈。
真实上游生成具有随机性，本轮使用导出样本和离线 SSE 重放，未以真实账号重新请求云端模型。

全量验证：57 个 Go 测试包、420 项 Node 测试、lint、源码大小门禁及前端生产构建通过；另有 2 项依赖外部 SDK 资源的测试按规则跳过。本修复随 v4.6.8 主程序提供，SDK 资源仍可使用 v4.6.7 扩展包。
SSE、标准 Turn、共享重试及四协议流式路径共 7 个包的竞态检查通过。
