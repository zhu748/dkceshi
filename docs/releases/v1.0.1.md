# v1.0.1

本次修复账号自动换号与文件、会话、PoW 之间的恢复边界，保留现有轮询和粘性调度规则。

- 带原始附件的请求在上传成功后遇到限流、禁言、封禁或鉴权失败，仍可切换账号并完整重建附件、HISTORY/TOOLS 和会话；已有文件 ID 且缺少原始字节的请求继续固定账号。
- 首发与换号重启复用执行入口，临时账号固定独立于用户指定账号；纠正生成获取 PoW 时也保护当前会话的归属，明确账号失败不再复用旧证明继续发送。
- 上下文和附件上传接入每账号一次的鉴权恢复，刷新失败后尝试健康账号，避免同一次拒绝被内外两层重复计入连续鉴权失败。
- Vercel 流式逐次检查首发、纠正生成和换号响应中的账号错误，封禁 JSON 正确禁用账号，HTTP 429 与业务限流按既有两分钟策略冷却；缺少截止时间的禁言与 Go 一致兜底十分钟。
- prepare、租约和后续重试使用实际重建后的标准请求，保留请求原有模型和工具策略；原始附件与重放回调不进入诊断或 prepare JSON。
- 普通网络断开、`get pow failed` 等错误不会仅因错误文本被判成限流冷却。已经交付正文或工具调用的请求保持原有防重放边界。

回归覆盖附件上传后的上下文、会话、PoW、回复阶段失败，轮询/粘性、历史拆分开关、四种协议的流式与非流式、连续换号响应及鉴权计数。

检查包括 Go/Node 完整单元测试、Go 格式与静态检查、文件行数门禁、WebUI 构建，以及 Linux、macOS、Windows 共七种发布目标构建。
