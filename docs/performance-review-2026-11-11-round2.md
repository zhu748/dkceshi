# 2026-11-11 后续审查：上传复用、聊天记录与续写释放

本轮接续 [上一轮管理查询与统计优化](./performance-review-2026-11-11.md)，保留其全部修改，进一步检查共享上传、流式解析、自动续写与聊天记录页面的请求生命周期。

## 修复和优化

| 范围 | 发现的问题 | 完成的修改 |
| --- | --- | --- |
| 上传缓存 | 一个凭据失效会递增全局世代，使其他凭据正在上传/核验的结果也失去合并和缓存资格 | 将失效标记绑定到任务所属凭据，仅作废对应任务；保留原有容量、有效期、元数据副本和上游核验 |
| 大文件复用 | 初次构造缓存键、上游核验/上传后的身份复核都计算整个文件的 SHA-256 | 每次调用计算一次原始内容摘要；结束时仍重新读取当前凭据、设备身份和配置核对缓存键 |
| SSE 解析 | 每个普通字符串增量都为 8 个内容片段分配容量，常见路径实际只有一个片段 | 字符串增量预留 1 个槽位；结构化批量帧保留原容量和解析路径 |
| 聊天记录列表 | 列表读取没有请求身份和来源隔离；迟到响应可能撤销删除/清空/裁剪后的页面状态 | 提取 `useChatHistoryList.js`，集中管理读取、验证器、轮询和写入；写入前作废旧读请求并暂停轮询，写入之间同步互斥 |
| 聊天记录来源切换与卸载 | 列表与写操作可能在旧页面结束后提交；定时器持有旧请求来源 | 切换来源和卸载时取消读写；迟到响应与 JSON 解析受请求身份约束；新来源渲染时不暴露旧列表 |
| 304 恢复 | 网络恢复后返回 304，旧网络错误可能继续显示；没有已接受快照的 304 被当作成功 | 有效 304 清除旧错误；缺少有效验证器时显示可重试的读取错误 |
| 自动续写释放 | `Close` 只触发异步取消，关闭返回后底层读取仍可能接受数据 | 在读取前登记当前上游响应体，消费者关闭时同步关闭；关闭后才返回的续写响应立即关闭，共享单次关闭所有权 |

上传缓存的跨凭据问题由新增回归测试在修复前复现：A 上传过程中使 B 失效，A 的第二次同文件请求发生重复上传。修复后只上传一次，B 的条目仍正常清除。

自动续写问题在整包竞态检查中触发已有的 `TestAutoContinueCloseUnblocksUnderlyingBody` 失败，属于关闭顺序问题。修复后补充当前续写体、关闭后迟到的续写体、重复关闭及清理错误传播测试，并在 `-race` 下重复运行关闭相关测试 100 次。

- 新增 `useChatHistoryList.js`（131 行），复用已有 `createLatestRequest` / `createRequestGroup`，承载列表 ETag、轮询、保存保留条数、删除与清空逻辑。

## 本地基准

Go 1.26.10 / Linux amd64，`GOMAXPROCS=2`。先后编译优化前后测试二进制，按相同参数顺序执行，每组 5 次、`benchtime=700ms`。下表使用中位数；机器负载影响耗时，不代表真实上游响应延迟。

| 场景 | 优化前 | 优化后 |
| --- | ---: | ---: |
| 1 MiB 文件复用并核验元数据 | 1.87 ms | 1.66 ms |
| 16 MiB 文件复用并核验元数据 | 32.04 ms | 28.83 ms |
| 普通文本 SSE 帧解析 | 6.67 µs / 2160 B | 5.41 µs / 1888 B |
| 中文 SSE 帧解析分配 | 2192 B | 1920 B |
| 8 片段批量 SSE 帧解析分配 | 10055 B / 122 次 | 10055 B / 122 次 |
| 512 帧 SSE pump | 4.51 ms / 909243 B | 3.70 ms / 769972 B |

普通字符串帧每次少分配 272 B；512 帧 pump 的分配字节减少约 15%。分配次数不变，节省的是每个片段切片的预留空间。上传路径对文件内容的摘要扫描从两遍变为一遍，元数据 HTTP 请求及其解析仍存在；本地实测耗时减少约 10%，不据此声称整体耗时减半。上传基准确认每轮都进行了元数据核验，没有通过跳过核验获取性能收益。

复现入口：

```bash
GOMAXPROCS=2 go test ./internal/deepseek/client -run '^$' \
  -bench '^BenchmarkUploadReuseLargeFile$' -benchmem -benchtime=700ms -count=5
GOMAXPROCS=2 go test ./internal/sse -run '^$' \
  -bench '^Benchmark(ParseContentFrame|ParsedLinePump)$' -benchmem -benchtime=700ms -count=5
```
