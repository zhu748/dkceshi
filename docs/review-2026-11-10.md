## 项目主链路与审查范围

项目把 DeepSeek Web 能力转换为 OpenAI Chat / Responses、Claude、Gemini 兼容接口。协议入口通过 `promptcompat` 归一化请求，`prompt` / `contextfile` 保留消息、工具历史及附件上下文；`completionruntime` 负责会话、PoW、重试及换号；`sse` / `stream` 与 `assistantturn` 收集并校验输出，最后由协议边界渲染。Vercel 的实时 SSE 由 Node 桥接，共享 Go prepare / release 和最终校验。

本轮阅读和追踪的重点包括：账号池和鉴权恢复、空输出与工具错误重试、修复模型路由、Schema 编译缓存、SSE 快照及结束状态、流式输出交付、响应归档及用量统计，以及管理台请求取消和过期状态处理。修复集中在有明确代码证据和可复现用例的路径。

## 第一轮：结束帧与消息 ID

| 问题 | 影响 | 修复 |
| --- | --- | --- |
| 成功结束状态没有释放思考解析器暂存的分隔符前缀 | 尾部文本在 Stop 之后才出现，消费端已结束 | 在成功结束帧中先释放暂存文本 |

## 第二轮：Go / Node 一致性与修复账号归属

| 问题 | 影响 | 修复 |
| --- | --- | --- |
| BATCH 内遇到 FINISHED 立即返回 | 同帧后续正文丢失 | Go / Node 均扫描该帧全部补丁后结束 |

## 第三轮：关闭响应记录时的性能

关闭响应记录、保留用量统计时，旧代码仍会构造用户输入、消息副本、工具快照和 ContextManifest；向已关闭的历史存储更新时还会使用空记录 ID。

现在先判断历史记录是否启用。只需要用量统计时直接创建轻量状态，保留成功/取消统计需要的标准请求，跳过归档构造与历史写入。

基准：`BenchmarkStartUsageOnlyLargeContext`，约 768 KiB 的消息、提示词及工具说明，各版本同一环境、一次基准运行：

| 指标 | 修复前 | 修复后 |
| --- | ---: | ---: |
| 每次初始化耗时 | 15,627,490 ns | 697.9 ns |
| 每次分配内存 | 4,416,069 B | 1,072 B |
| 每次分配次数 | 129 | 4 |

该结果只衡量关闭历史记录时的初始化分支，不代表上游生成或端到端请求速度。新增用例验证：关闭历史时不创建归档，取消请求仍计入用量。

## 后续迭代：连接回收、限速唤醒与测试面板 SSE

本次从 `db877f3` 继续审查，阅读账号池/鉴权恢复、共享 completion 重试、Go/Node SSE 生命周期、历史与用量持久化、Responses 存储和管理台异步请求。环境补齐了 WebUI 依赖、Go 模块和代理模块所需的自动工具链。验证使用主模块 Go 1.26.10、代理模块 Go 1.27.3 和 Node 24.22.1。

### 第一轮：复用连接被旧定时器回收

HTTP/2 空闲连接超时回调可能已经开始、正在等待连接池锁。此时 `Timer.Stop` 无法撤回它；如果同一连接先被取出、使用、再次归还，旧回调仅按连接指针查找，会误关闭新一轮空闲连接。

为每次归还记录独立的 `idleVersion`，回调持锁后先核对版本。回归测试模拟旧回调迟到并验证连接继续复用，也验证当前版本的超时仍正常关闭连接。移除版本检查后，新测试稳定失败；修复后连接池相关用例通过。

### 第二轮：限速窗口过期但排队请求未唤醒

状态查询或取号扫描可先于定时器发现窗口过期。旧代码会清零并停止定时器，却没有执行定时器原本负责的唤醒动作，导致已有请求继续等待直到自身超时。

现在惰性过期也唤醒等待队列。通知函数同时识别构建可用账号视图期间发生的全队列唤醒，避免再次移除或关闭同一个 waiter。新增两个用例分别覆盖状态探测与通知扫描路径，在原代码上均失败，修复后通过。

### 第三轮：测试面板 SSE 正确性和性能

- 支持 CR、LF、CRLF 换行，包括跨字节分片的 CRLF、UTF-8、BOM、工具增量、EOF 尾帧与 `[DONE]` 后忽略尾部。
- 扫描只处理新收到的分片，未完成的行按片段保留；行结束时才拼接，避免对不断增长的尾部重复搜索。
- 测试面板采用共享默认预算的数值：单行和单事件各最多 8,388,608 个 UTF-16 代码单元，流响应原始字节总量最多 32 MiB；超限报告错误并取消 reader。浏览器预算不读取服务器环境变量。

Node 24.22.1、Linux amd64，基线 `db877f3` 与改动版使用相同 reader 接口、内容和分片。交替测量，预热两次后取五次中位数；不包含真实网络和 React 渲染：

| 场景 | 原耗时 | 改动后耗时 |
| --- | ---: | ---: |
| 64 KiB 单事件，256 B 分片 | 2.308 ms | 0.981 ms |
| 1 MiB 单事件，256 B 分片 | 736.434 ms | 7.558 ms |
| 512 个普通小事件，4 KiB 分片 | 1.099 ms | 1.168 ms |

大事件碎片化场景约快 97 倍；普通小事件增加约 0.07 ms，包含新增换行处理与资源检查的开销。本结果只说明浏览器测试面板的本地解析性能。

复现命令：`node --expose-gc tests/tools/benchmark-api-tester-stream.mjs db877f3`。
