# 2026-11-10 项目审查与优化

基于 `main` 的 `9c65ac4`，按“阅读调用链、构造边界用例、修复、复核”进行迭代。

## 项目主链路与审查范围

项目把 DeepSeek Web 能力转换为 OpenAI Chat / Responses、Claude、Gemini 兼容接口。协议入口通过 `promptcompat` 归一化请求，`prompt` / `contextfile` 保留消息、工具历史及附件上下文；`completionruntime` 负责会话、PoW、重试及换号；`sse` / `stream` 与 `assistantturn` 收集并校验输出，最后由协议边界渲染。Vercel 的实时 SSE 由 Node 桥接，共享 Go prepare / release 和最终校验。

本轮阅读和追踪的重点包括：账号池和鉴权恢复、空输出与工具错误重试、修复模型路由、Schema 编译缓存、SSE 快照及结束状态、流式输出交付、响应归档及用量统计，以及管理台请求取消和过期状态处理。修复集中在有明确代码证据和可复现用例的路径。

## 第一轮：结束帧与消息 ID

| 问题 | 影响 | 修复 |
| --- | --- | --- |
| 成功结束状态没有释放思考解析器暂存的分隔符前缀 | 尾部文本在 Stop 之后才出现，消费端已结束 | 在成功结束帧中先释放暂存文本 |
| 非合并路径丢弃普通结束帧自带正文 | 批量结束帧的答案或工具参数尾部丢失 | 先转发内容，再转发 Stop |
| 非合并路径不即时传递无正文的消息 ID | 连接在下一内容帧前断开时缺少续传标识 | 保留独立的 ID 元数据帧 |

`terminal_delivery_test.go` 覆盖合并/直发、思考尾部、批量正文、仅 ID 后断流。修复前可复现结束帧丢内容及 Stop 后发内容，修复后 SSE 与流式引擎包检查通过。

## 第二轮：Go / Node 一致性与修复账号归属

| 问题 | 影响 | 修复 |
| --- | --- | --- |
| BATCH 内遇到 FINISHED 立即返回 | 同帧后续正文丢失 | Go / Node 均扫描该帧全部补丁后结束 |
| 完整 response 快照的 CONTENT_FILTER 状态未识别 | 过滤响应可能被当作普通答案或错误重试 | 识别 response 的 status / quasi_status，保留正文字符串的字面含义 |
| 原模型工具修复未固定账号 | 创建会话后，PoW 内部恢复可能切到其他账号，造成会话与凭据不匹配 | 以操作级账号固定覆盖整个修复过程，结束后释放 |

新增 Go / Node 对应用例；原模型修复使用真实 Resolver 与双账号池验证：PoW 阶段尝试换号不会改变修复会话归属，主请求也不会被该子操作换号。

## 第三轮：关闭响应记录时的性能

关闭响应记录、保留用量统计时，旧代码仍会构造用户输入、消息副本、工具快照和 ContextManifest；向已关闭的历史存储更新时还会使用空记录 ID。

现在先判断历史记录是否启用。只需要用量统计时直接创建轻量状态，保留成功/取消统计需要的标准请求，跳过归档构造与历史写入。

基准：`BenchmarkStartUsageOnlyLargeContext`，约 768 KiB 的消息、提示词及工具说明，各版本同一环境、一次基准运行：

| 指标 | 修复前 | 修复后 |
| --- | ---: | ---: |
| 每次初始化耗时 | 15,627,490 ns | 697.9 ns |
| 每次分配内存 | 4,416,069 B | 1,072 B |
| 每次分配次数 | 129 | 4 |

该结果只衡量关闭历史记录时的初始化分支，不代表上游生成或端到端请求速度。新增用例验证：关闭历史时不创建归档，取消请求仍计入用量。
