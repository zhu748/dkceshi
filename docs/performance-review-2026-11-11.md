## 已完成修改

### 账号和自动设备列表

- 用 `Store.Accounts()` 读取隔离的账号快照，避免复制代理、模型别名和其他无关配置。
- `account_list.go` 用索引完成筛选和稳定分组，复杂度从稳定排序的 O(N log N) 降为 O(N)，避免排序时反复交换完整账号结构体。
- 自动设备列表先筛选、分页，再为当前页构造响应对象；`total_all` 从同一次账号快照计算，避免再次复制配置。
- 账号列表保持“配置倒序、可调度优先”；设备列表保持“配置正序、启用且未禁言优先”。设备管理的资格规则继续与调度资格分别表达。
- 搜索、状态计数、空页、越界页、字段脱敏和分页上限保持原有语义。新增跨分页顺序、混合状态和搜索计数测试。

### 用量统计

- `summary.go` 复用定时账本检查点已有的键顺序。读取仍在同一把锁下复制当前数值和版本，锁外以线性操作反转日期分组，保持同日期内模型/调用方/账号升序。
- 新键出现时回退到完整排序；清空、导入和账本替换沿用现有检查点失效机制。没有新增计数缓存或改变 ETag、磁盘格式、费用计算口径。
- `pricing.go` 从 `usage.go` 拆出模型匹配、缓存计价和波峰日期判定。模型候选改为单次扫描选取最长匹配，等长时保持原有字典序规则，精确匹配与零价格优先级不变。
- 测试覆盖检查点前后顺序、最新计数/标签、同条数替换、返回值隔离、价格匹配边界和并发 revision 一致性。

### 前端轮询

- 队列请求尚未完成时跳过下一轮定时触发，避免慢网络下每五秒取消旧请求并重新开始。
- 定时器读取当前请求函数；更换 `apiFetch` 时取消旧来源的请求并重新加载。
- 旧响应、旧 JSON 解析和旧请求的收尾仍受请求身份约束，卸载会清理请求和定时器。
- 两项新增回归测试在修复前均失败，修复后通过：慢队列请求最终可提交结果；更换来源后旧响应不能覆盖新页面。

## 基准结果

同一 Linux amd64 环境，Go 1.26.10，`GOMAXPROCS=2`。优化前后分别编译测试二进制，顺序运行相同基准，每组五次、`benchtime=800ms`，表中为中位数。机器负载会影响耗时，不能据此推算上游模型响应延迟；分配量和复杂度变化更稳定。

| 场景 | 优化前 | 优化后 | 耗时减少 |
| --- | ---: | ---: | ---: |
| 5000 账号，账号列表第 2 页，每页 10 条 | 9.31 ms | 3.52 ms | 约 62% |
| 5000 账号，设备列表第 2 页，每页 10 条 | 12.75 ms | 2.41 ms | 约 81% |
| 1 万用量条目，已有有效检查点 | 9.16 ms | 3.62 ms | 约 61% |
| 10 万用量条目，已有有效检查点 | 108.90 ms | 45.37 ms | 约 58% |
| 5 个候选价格，匹配 search/nothinking 模型 | 4.31 µs | 0.68 µs | 约 84% |

设备列表每次分配从约 8.50 MB / 15117 次降至 2.29 MB / 140 次，分配字节减少约 73%。普通账号列表增加一份轻量索引空间，分配从约 2.27 MB 增至 2.35 MB（约 3.5%），换取线性处理并省去全账号结构体排序。计价候选匹配从 840 B / 7 次临时分配降至 0；统计读取的返回快照仍独立分配，不与可变账本共享。

复现入口：

```bash
GOMAXPROCS=2 go test ./internal/httpapi/admin/accounts \
  -run '^$' -bench '^BenchmarkAccountLists/5000/' -benchmem -benchtime=800ms -count=5
GOMAXPROCS=2 go test ./internal/usagestats \
  -run '^$' -bench 'Benchmark(SummaryStableLedger|MatchModelPrice)$' -benchmem -benchtime=800ms -count=5
```

## 后续优化边界

- 图表已按需注册并由独立懒加载块承载；ECharts 构建块仍超过 500 kB，会产生体积提示。进一步减小体积应以实际首屏和图表交互测量为依据。
- 部分协议、工具解析和代理管理文件仍较大，行数门禁保留已有上限。继续拆分应围绕明确职责，并保持 Go/Node、各协议共享业务规则的回归覆盖。
- 聊天历史仍在 Store 锁内执行文件写入，保留了原有提交语义。异步化需要单独验证写失败恢复、删除/裁剪与重启一致性，本轮没有修改该部分。
- 未使用真实账号进行上游联网压测，也未执行实际生产部署；本轮结论来自源码审查、本地测试、构建和合成数据基准。
