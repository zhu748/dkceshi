# 工具调用历史的离线诊断

## 样本与可确认结论

本轮用户提供的 `chat_history.zip` 包含 17 条响应详情：13 次主请求、4 次 `toolcall.repair`。
它覆盖一段连续 Agent 工具循环，包括调用格式、后续工具执行结果和最后的普通回答。
原包和业务源码内容未加入仓库；回归测试使用合成样本。

13 次主请求的 `final_prompt`、`history_text` 及归档消息中均没有 DSML 字样，且均带有当前
调用者自定义格式提醒。返回正文有 4 次完整 DSML、1 次夹杂 DSML 闭合标签的混合输出。
因此样本中的 DSML 来自上游返回阶段，不能归因于输入历史里的 DSML 示例。
[DeepSeek 官方 V4.1 编码说明](https://huggingface.co/deepseek-ai/DeepSeek-V4.1-Flash/blob/main/encoding/README.md)
本身就定义了 DSML 的 `calls/invoke/parameter` 及 `string` 属性；样本还存在重复竖线等格式漂移。
仅靠文字提醒没有原生结构化输出的语法约束。缺少上游 token ID 与完整传输记录，
不能进一步断定是模型直接写出文本，还是上游服务暴露了内部格式；长上下文是否增加了漂移概率也需单独对照实验。

| 观察 | 证据与影响 | 本轮处理 |
|---|---|---|
| 四次完整 DSML 输出仍请求模型修复 | 主请求中出现完整原生 DSML，随后各有一条修复记录；四条修复耗时合计 9,923 ms | 增加严格的本地 DSML 恢复，未知/不完整结构保留原有兜底 |
| 重复闭合标签和消息结束标记 | 原始响应出现额外闭合标签，后续请求还带回了漏出的结束标记 | 使用跨分片保护和孤立闭合标签清理；不删除工具参数、Markdown 示例中的字面量 |
| `messages` 归档缺失工具调用轮次 | 一个后续详情只有 2 个 assistant 消息，但其最终提示词含 12 个历史 assistant 轮次；纯工具调用在归档提取时被空 content 判断删除 | 统一共享归档提取器，保留结构化调用、结果关联 ID、错误状态和空工具结果 |
| 输入上下文负担较重 | 13 次主请求合计记录 2,656,584 个输入 token，单次 184,715～230,021；历史外置文件仍计入完整输入 | 保留已有活动工具链切分，不自动删除客户端历史；后续可由调用端压缩已完成结果、限制重复文件读回 |

本地回放在 12 个工具调用回合中恢复了 24 个调用，另有 1 个普通回答回合。
四个原生 DSML 回合的恢复结果与包内对应 LLM 修复输出的工具名、参数类型、参数值摘要全部一致，
包含两个双调用批次及两个单调用批次。这里的 9,923 ms 是旧记录中的修复耗时，
不代表已经完成真实上游性能压测或保证同样的线上提速。

旧归档的 `content` 由归档代码优先保存原始模型文本，并非客户端最终收到的完整 JSON；
`success` 也表示代理请求完成，不表示所有工具执行及业务测试成功。
不能仅凭原始 `content` 中有 XML/DSML，就认定客户端收到的是未解析文本。
本包可以定位格式漂移、恢复代价、上下文组成和后续执行结果，但没有完整 SSE 分片、正式工具目录快照，
也没有逐帧的最终交付内容。因此历史中的缺参、流式时序和 call ID 配对不能全部从旧记录反推。

## 本地回放

### 2026-10-30 参数标签简写样本

追加的 `chat_history.json.d.zip` 含 12 条主请求、0 条修复子请求，均保存了正式工具 schema。
原逻辑回放复现 5 次 `invalid_tool_arguments`：4 次 pwsh 缺 description，1 次 edit 批次缺
old_string / new_string。原文实际带有这些字段和值，但开标签被写成
`<|NTNAFD|description">` / `<|NTNAFD|old_string">`，旧扫描器忽略后只保留其他参数，
且将调用误判为完整成功，因此未进入 LLM 修复。

扫描器恢复该明确的参数外壳后，同一包的 12 条记录均通过共享收尾和正式 schema 校验，
共解析 27 个调用，未请求模型。原来成功的 7 条记录的参数摘要保持一致；这属于离线解析验证，
没有执行归档内的命令或编辑，也不代表已经完成真实上游联调。回归用合成样本，不提交原包。

### 运行命令

在仓库目录运行：

```sh
go run ./cmd/history-replay -archive /path/to/chat_history.zip
```

命令只在本地读取 ZIP 和运行共享收尾/解析逻辑；不会执行工具、调用上游、写回或解压原包。
输出 JSON，包含记录数量、本地恢复数量、工具名、参数名、参数 JSON 的 SHA-256、回放错误码，
并标明每条记录是否有正式 schema。新归档提供 schema 时会执行参数校验；旧包缺少 schema 时
不会把“成功解析”表述为“通过 schema 校验”。修复子请求单独统计，不重复计入主流程工具调用数。
读取上限为单条详情 32 MiB、全部详情 256 MiB；超出时报告错误。

新记录保留 `tool_calls`、`function_call`、`tool_call_id`、`name`、`is_error`、
`reasoning_content`、`prefix`，以及 `tools`、`tool_choice_policy`、`tool_marker`。
历史面板同时显示消息正文与结构化字段。仍需原始分片诊断时，应另外启用项目已有的 raw sample 采集；
本地归档快照不会补造旧记录中不存在的信息。
