# 核心链路循环审查与修复

## 空输出的重试记录与停止原因

工具请求即使没有产生任何工具标记，纯空响应及账号级失败也会保存到工具调用诊断。
换号尝试在新账号开始准备会话、文件和 PoW 之前登记，准备阶段失败也会保留，
不会仅在新账号成功返回响应后才补记。流式终止日志与非流式结果的重试次数包含换号，
避免换号成功后仍显示 `retry_attempts=0`。

停止换号的诊断区分：显式指定账号、客户端文件归属绑定、操作暂时锁定账号、
请求取消、最多三次换号的请求总额度耗尽、三十秒累计等待耗尽、没有符合条件的替代账号。
上游返回的空消息错误保留原有错误码，具体停止原因显示在该尝试的重试决策中。
工具请求的空输出失败不再因没有进入工具解析而缺失；普通成功文本仍不额外建立诊断。

纯空输出与仅思考的 429 在托管号池中继续使用一分钟冷却并立即换号的共享策略。
连续空响应会继续尝试未使用且符合条件的账号，直到成功或触及上述约束。
面板上存在账号不代表它符合本请求的号池类型、冷却、并发、频次及日额度条件。

## 2026-11-08：账号冷却与故障切换

账号的启用开关表示允许调度，不代表当前可用；临时冷却独立记录在 `cooldown_until`，
不会替用户关闭开关。明确的 429（包括仅输出思考内容后的限速）以及已识别的无输出
`upstream_unavailable` 会记录至少一分钟冷却，再尝试其他可调度账号，避免先在原账号重新生成。
普通网络错误或未分类的 503 不直接视作账号限速。上游禁言仍使用其实际恢复时间，
并与一分钟限速冷却分别显示；永久封禁不自动恢复。

冷却记录不再依赖重试是否启用、是否还有替代账号或是否已结束流式输出。
OpenAI Chat、Responses、Claude、Gemini 共用相同的失败状态观察与切号决策。
Vercel Node 路径在释放请求时也回传失败状态，并用内部账号 ID 校验归属，
避免切换途中失败后把旧账号错误记到新账号。没有向客户端暴露该内部归属信息。
封禁错误与禁言错误一样，在尚未交付答案或工具调用时允许切号重试。

Go 与 Node 上游 JSON 检测都支持有界的空白前缀，并保留流内容原样重放；
响应体以空格或换行开头时，不再因此漏判封禁、禁言或限速。
账号面板新增冷却状态、恢复时间和筛选，每五秒按当前搜索、分页与筛选条件刷新。
封禁、禁言和手动禁用的展示优先于冷却，启用数量与实际可调度数量仍分别统计。

切号失败的日志补充显式选号、已有文件归属绑定、重试预算耗尽和无可用替代账号的原因。
文件归属和显式选号约束保持有效，已发送的答案或工具调用也不会被重放。
仅凭面板截图不能确定某次请求具体被哪条约束阻止；日志用于区分这些情况。

回归测试覆盖：仅思考后 429 直接换号、无替代账号/禁用重试时仍冷却、终止流的失败观察、
JSON 跨分片空白前缀、Node 切号的限速标记与账号归属、面板冷却筛选与定时刷新。
本轮验证：69 个 Go 包通过；Node 699 项通过、2 项外部 SDK 环境用例跳过；
Lint 0 问题；WebUI 构建通过；行数门禁扫描 971 个源文件，无缺失或超限。

## 已修复问题

| 轮次 | 复现的问题 | 修复后行为 |
| --- | --- | --- |
| 1：文件恢复 | 400/401/403/422 轮询重复请求 60 次 | 永久错误立即退出；托管账号最多在原账号刷新一次，临时 408/429/5xx 保留重试 |
| 1：复用判断 | HTML、空响应、null、缺失文件列表会被当成文件不存在，导致重传 | 成功响应必须能解析为对象；无法确认缺失时保留旧缓存并返回异常 |

| 1：响应内存 | gzip/br 元数据响应可以无限解压读取 | 解压后最多读取 16 MiB + 1 字节，超限报错；不影响 SSE 或文件原始上传大小 |
| 2：正文缓存 | 总容量无上限、写入不清理过期项、外部修改字节会污染缓存 | 256 MiB / 256 项硬上限、写入回收过期项、复制读写缓冲区、准确扣减替换/删除的容量 |
| 2：设置缓存复查 | 所谓 128 项限制只清理过期项，150 个有效键仍保留 150 项 | 128 项硬上限；不淘汰正在查询的项，满载时使用显式/默认设置 |
| 3：流式传输 | gzip 响应取消后读取挂起、响应头前关闭不结束请求 | 对实际解压后的正文传播错误，关闭 HTTP/2 流和会话，移除取消监听器 |
| 3：断连复查 | gzip 源流错误没有自动传到解压流 | RST_STREAM 和取消都使正文读取失败；正常 SSE/gzip 及主动取消读取仍正常 |
| 4：请求入口 | 无需正文的鉴权拒绝也预读整个正文；第一段 JSON 后的其他 JSON/垃圾被忽略 | 首次读取才验证，严格检查完整 UTF-8 与单个 JSON 值 |

## 验证方式

- Go 回归覆盖损坏元数据不重传、永久/临时错误分流、原账号刷新成功/再次失败、响应关闭及 gzip/br 解压大小限制。
- 缓存回归覆盖字节隔离、并发读取、过期回收、容量淘汰、覆盖/重复删除记账和空文件数量上限。
- Node 使用本地真实 HTTP/2 服务复现取消、RST_STREAM、响应头前关闭以及 gzip 正常结束。
- 请求入口回归覆盖授权提前拒绝不读正文、多个拼接 JSON、尾随垃圾，以及既有 UTF-8 行为。
- 全量检查使用仓库规定的 Lint、Go/Node 单测、行数门禁和 WebUI 构建；另外对受影响 Go 包运行 race 检测。

最终结果：Lint 0 问题；Go 全量测试通过；Node 295 项通过，1 项依赖外部 SDK 运行环境的既有测试跳过；
client、files、requestbody、server 四个 Go 包 race 检测通过；WebUI 构建通过。
行数门禁命令退出成功，但当前目标清单为空，报告 `checked=0`，不能视为已扫描所有文件的行数。
WebUI 构建仍有既有的大 bundle 提示，本轮没有混入前端打包拆分。

## 边界

本轮不改变每次普通请求新建上游会话的策略，不改变账号调度和显式文件的账号绑定。
旧 file_id 能否用于真实上游的新对话、删除会话后的文件生命周期仍需要授权环境中的集成验证。
HAR 不能证明 TLS ClientHello/JA3/JA4 等价，本轮没有据此修改 TLS 指纹。
缓存总量为缓存持有内容的限制，不是进程总内存上限；并发请求本身仍需要额外的正文和解码内存。
审查与本地测试不构成对所有上游状态或部署环境的无缺陷保证。
